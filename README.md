# dashboard_web (ONE SCHEDULER)

개인 일정과 그룹 일정을 한 곳에서 관리하는 캘린더 웹 앱의 프론트엔드(Next.js App Router)입니다.
백엔드 API는 이 저장소에 포함되어 있지 않으며, `NEXT_PUBLIC_SERVER_IP`로 지정한 별도 서버를 호출합니다.

## 요구 사항

- Node.js 20+
- 별도로 실행 중인 백엔드 API 서버 (인증, 일정, 그룹, 공휴일/날씨 프록시 등)

## 환경 변수

`.env.local`을 만들어 아래 값을 채워주세요.

| 변수 | 설명 |
| --- | --- |
| `NEXT_PUBLIC_WEB_IP` | 프론트 자체 오리진. Playwright e2e의 `baseURL`로 사용 (예: `http://localhost:3000`) |
| `NEXT_PUBLIC_SERVER_IP` | 백엔드 API 오리진. 브라우저(axios)와 서버 컴포넌트 양쪽에서 호출하므로 공개 변수 (예: `http://localhost:8080`) |
| `KAKAO_REST_API_KEY` | 좌표→주소 변환(`/api/address`)에 쓰는 카카오 REST API 키. **서버에서만 사용**하므로 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다 |
| `E2E_EMAIL` / `E2E_PASSWORD` | Playwright 로그인 테스트용 계정. 없으면 해당 테스트는 자동으로 skip됩니다 |

## 인증 흐름

- 로그인 성공 시 백엔드가 `access-token` 쿠키(및 refresh 쿠키)를 내려줍니다.
- `src/middleware.ts`가 보호 라우트(`/`, `/schedule`, `/group`, `/profile`) 진입 시 `access-token` 쿠키 유무를 검사하고, 없으면 리프레시를 먼저 시도한 뒤에도 실패하면 `/login`으로 리다이렉트합니다.
- 브라우저에서의 401/403은 `src/lib/api.ts`의 axios 인터셉터가 `/token-refresh`를 호출해 자동 재시도합니다.

## 디렉터리 구조 (요약)

```
src/
  app/            App Router 페이지 및 API 라우트
  components/     기능별 UI 컴포넌트 (common, home, group, schedule, ui)
  hooks/          react-query 훅(querys), zustand 스토어(stores)
  lib/            axios 인스턴스, 서버 전용 fetch, 인증 유틸
  types/          API 응답/요청 타입
  utils/          날짜·일정 계산 순수 함수
```

## 디자인 시스템 메모

색은 전부 `globals.css`의 CSS 변수로만 정의하고, 컴포넌트는 `bg-surface` / `text-foreground` 같은
시맨틱 토큰만 사용합니다. `text-white`, `text-slate-400` 같은 고정 색을 컴포넌트에 직접 쓰면
테마 전환 시 배경만 바뀌고 글자는 그대로 남아 안 보이게 되므로 쓰지 않습니다.
(예외: 배경이 테마와 무관하게 고정인 요소 — 브랜드 색 뱃지, 액센트 버튼 위의 흰 글씨 등)

표면 표현은 세 가지로만 씁니다.

| 유틸리티 | 용도 | 형태 |
| --- | --- | --- |
| `neu-flat` | 카드, 리스트 행 등 대부분의 콘텐츠 면 | 솟아오름 (`--elevation-1`) |
| `neu-float` | 더 떠 있어야 하는 요소 (브랜드 히어로 등) | 크게 솟아오름 (`--elevation-2`) |
| `neu-pressed` | 입력창, 캘린더 그리드, 토글 트랙 | 안으로 파임 (`--inset-1`) |

- 솟은 면은 **상단 1px 베벨 하이라이트 + 우하단 그림자** 조합으로 표현합니다. 이 베벨이 없으면
  같은 그림자여도 사람 눈에는 "구멍"으로 읽힙니다.
- 표면색(`--surface`)은 항상 배경(`--main-bg`)보다 한 단계 밝아야 합니다. 같거나 어두우면 파여 보입니다.
- 그림자 색은 불투명 회색 대신 반투명(`rgba`)으로 씁니다. 불투명이면 요소가 인접할 때 경계가 띠처럼 보입니다.
- 테마는 `theme` 쿠키로 저장하고 `layout.tsx`가 서버에서 읽어 `<html data-theme>`으로 렌더링합니다.
  클라이언트에서 DOM 속성만 바꾸면 `router.refresh()` 시 서버 렌더링에 덮여 사라집니다.

## 기능 로드맵 (백엔드 / 프론트엔드 분담)

이 저장소는 프론트엔드만 포함하므로, 아래 항목은 백엔드 API가 먼저 준비되어야 합니다.

### 1. 일정 알림 / 리마인더
- **백엔드**: 일정에 "알림 시점" 필드 추가, 알림 발송 인프라(스케줄러/큐 + FCM 또는 웹푸시), 알림 이력 조회 API
- **프론트엔드**: 웹푸시 구독 등록(Service Worker), 생성/수정 폼의 알림 시점 선택 UI, 알림함 UI

### 2. 반복 일정
- **백엔드**: 반복 규칙(RRULE 등) 저장, 반복 회차 확장(occurrence) 조회 API, "이 일정만 / 전체" 수정·삭제 로직
- **프론트엔드**: 반복 설정 UI, 캘린더 뷰의 반복 일정 렌더링, 회차별 수정 옵션 모달

### 3. 외부 캘린더 연동 (ICS)
- **백엔드**: iCalendar(.ics) export 엔드포인트, 구독용 고유 URL 발급
- **프론트엔드**: "캘린더 구독 / 내보내기" 버튼, 구독 URL 안내 UI

### 4. 다중 그룹 소속
- **백엔드**: 유저-그룹 관계 1:1 → N:M 스키마 변경, 그룹별 권한 / 전환 API
- **프론트엔드**: 그룹 전환 스위처, 뷰 상태(`useScheduleViewStore` 등)를 그룹 단위로 확장

### 5. 일정 검색 서버화
클라이언트 검색은 이미 붙어 있으므로, 일정이 많아져 전체를 내려받기 부담스러워지면 전환합니다.
- **백엔드**: 기간·키워드 기반 검색 API (인덱싱 포함)
- **프론트엔드**: 기존 검색 UI의 데이터 소스만 교체, 최근 검색어 저장

### 6. 남은 프론트엔드 작업
- Sentry / Analytics SDK 연동 (계정 발급만 필요)
- 캘린더 뷰 컴포넌트 테스트, 시트 폼 동작 테스트
- `sheet.tsx` 분리, 캘린더 그리드 키보드 탐색
