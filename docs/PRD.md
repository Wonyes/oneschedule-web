| 항목 | 내용 |

## 1. 배경과 문제

일정 도구는 많지만 **"내 일정"과 "우리 팀 일정"은 늘 다른 앱에 흩어져** 있다. 개인용 캘린더에는 팀 일정이 없고, 팀 도구(슬랙·노션·구글 캘린더 공유)는 개인 일정과 겹치는지 알려주지 않는다. 결과적으로 사용자는 두 화면을 번갈아 보며 머릿속에서 합친다.

**ONE SCHEDULE**은 개인 일정과 그룹 일정을 **같은 캘린더, 탭 하나 차이**로 두고, 겹침을 화면에서 바로 드러내는 것을 목표로 한다.

## 2. 목표 / 비목표

### 목표
1. 개인·그룹 일정을 **한 화면**에서 보고 등록한다. 전환 비용은 탭 클릭 한 번.
2. 초대 코드 하나로 **가입부터 첫 일정까지 1분 안에** 끝난다.
3. 모바일(320px)에서도 캘린더가 **축소가 아니라 구조 변경**으로 동작한다.
4. 팀에서 일어난 변화(가입·일정 변경·참여자 지정)를 **알림으로 즉시** 안다.

### 비목표 (이번 버전에서 하지 않음)
- 외부 캘린더(구글·네이버) 동기화 — 네이버는 읽기 API가 없고, 구글은 민감 스코프 검수가 필요해 보류
- 반복 일정(RRULE), 웹 푸시, 결제·조직 관리

## 3. 사용자

| 페르소나 | 상황 | 핵심 니즈 |
| :--- | :--- | :--- |
| **팀 리더** (그룹 SUPER) | 5~15명 팀의 회의·마감 관리 | 팀 일정 등록 시 참여자 지정, 가입 승인, 권한 관리 |
| **팀원** (MEMBER/SUB) | 개인 약속과 팀 일정이 자주 겹침 | 내 일정 위에 팀 일정 겹침 표시, 참여자로 지정되면 알림 |
| **가족·동호회** | 초대 코드로 가볍게 참여 | 앱 설치 없이 링크·코드만으로 가입, 모바일 우선 |

## 4. 핵심 사용자 흐름

### 4.1 가입 (이메일 인증)
```
이메일 입력 → [인증 코드 받기] → 메일 6자리 코드 입력 → [인증하기] → 비밀번호 → 이름·닉네임 → 전화번호(선택) → 완료 → /login?welcome=1
```
- 코드 유효 3분, 재전송 60초 제한, 인증 후 30분 안에 가입해야 함 (백엔드 `EmailVerificationService`)
- 이미 가입된 이메일은 코드 발송 단계에서 409로 막힘
- Google OAuth 가입/로그인 병행

### 4.2 비밀번호 찾기
```
/find-password: 가입 이메일 → 코드 → 새 비밀번호 → /login?reset=1
```
- 같은 인증 API를 `purpose=PASSWORD_RESET`으로 재사용
- 가입되지 않은 이메일은 **가입 여부를 노출하지 않고** 조용히 200 (문구: "가입된 이메일이면 코드가 도착해요")
- 실제 변경은 `POST /members/password-reset` — 인증 없이는 403

### 4.3 일정
```
캘린더(월/주/일) → 빈 칸 클릭 → 시트(PC 모달 / 모바일 바텀시트) → 제목·시간·카테고리·참여자 → 저장
```
- 카테고리: 업무 / 개인 / 회의 / 중요 (색으로 구분)
- 그룹 일정은 참여자를 지정할 수 있고, 미지정이면 그룹 전원이 대상
- 등록자만 수정·삭제 (다른 멤버는 조회)
- 일정이 있는 날을 월 뷰에서 클릭하면 일 뷰로 이동, 없는 날은 바로 등록 시트

### 4.4 그룹
```
[둘러보기] 공개 그룹 검색 → 즉시 가입 또는 승인 요청
[코드 참여] 초대 코드 입력 → 즉시 가입
[만들기]   이름·직책 → 생성 → 초대 코드 발급
```
- 공개 범위: `PUBLIC_OPEN` (즉시) · `PUBLIC_APPROVAL` (승인) · `PRIVATE` (코드)
- 역할: `SUPER` (방장) · `SUB` (부관리자) · `MEMBER`
- 승인·거절·강제 탈퇴·권한 변경은 관리자만, 해체는 SUPER만

### 4.5 알림 (13종)
| 그룹 | 일정 | 계정 |
| :--- | :--- | :--- |
| 가입 신청 / 승인 / 거절 / 새 멤버 / 멤버 탈퇴 / 권한 변경 / 해체 | 생성 / 시간 변경 / 삭제 / 참여자 추가 / 참여자 제외 / 1시간 전 리마인더 | 비밀번호 변경 |

- SSE로 실시간 수신, 헤더 종 아이콘에 미읽음 배지, 대시보드에 최근 4건

## 5. 화면 요구사항

| 화면 | 필수 요소 |
| :--- | :--- |
| **대시보드** `/` | 인사·날짜·날씨, 일정 추가, 오늘/이번 주/가입 그룹 통계 칩, 이번 주 7일 스트립(날씨·일정 점), 오늘 날짜 중심 그룹 오빗, 시작 가이드(3단계, 완료 시 숨김), 다가오는 일정 타임라인(오늘·내일 항상 표시), 최근 알림, 미니 달력(공휴일), 활성 그룹 카드, 지평선 푸터(시각 따라 해·달 이동, 오늘의 한 줄) |
| **스케줄** `/schedule` | 다이얼 헤더(현재 기간이 가운데, 옆 눈금 클릭·휠·스와이프로 이동), 오늘 버튼, 일/주/월 토글, 오늘·내일 요약 한 줄, URL 동기화 `?view=&date=&type=` |
| **그룹** `/group`, `/group/[no]` | 둘러보기/코드 참여/만들기 탭, 그룹 히어로(오빗), 멤버·가입 신청·일정 타임라인·최근 활동 섹션 |
| **프로필** `/profile` | 원판 위 아바타 + 그룹 위성, 카운트업 통계, 계정 정보 인라인 수정, 비밀번호 변경 모달 |
| **인증** `/login` `/sign` `/find-password` | 브랜드 원판 + 스텝 폼, 인라인 에러(백엔드 메시지 그대로), Google 버튼 |

### 반응형
- `lg` 이상: 사이드바 + 본문, 쉘 최대 1400px 가운데 정렬, 본문 1200px
- `sm` 미만: 하단 탭바, 바텀시트, 주 뷰는 3일 페이징, 월 뷰는 점 + 아젠다
- 320px에서 가로 스크롤 없음

### 디자인 언어
1. **궤도** — 원판·점선 링·혜성·위성. "일정은 나를 중심으로 도는 것"
2. **뉴모피즘 촉감** — 떠 있으면 누를 수 있고, 눌려 있으면 입력하거나 담는 곳. 색이 아니라 깊이로 의미 구분
3. **살아 있는 시간** — 날씨 아이콘, 시각 따라 움직이는 해·달, 카운트업
4. **말투** — 작은 대문자 눈썹 라벨 + 부드러운 존댓말 ("오늘은 비어 있어요")

## 6. 비기능 요구사항

| 항목 | 기준 |
| :--- | :--- |
| 인증 | HttpOnly 쿠키 JWT(access 30분 / refresh 7일, 기기별), 미들웨어 + 인터셉터 single-flight 재발급, 401/403은 항상 `ErrorResponse` JSON |
| 에러 처리 | 프론트는 백엔드 `message` / `result[].reason`을 그대로 표시, 클라이언트 분기 없음 |
| 성능 | 서버 프리페치로 첫 화면 스켈레톤 없음, N+1 제거(배치 조회), 날씨 배치 upsert, 테마 전환 시 애니메이션 일시정지 |
| 접근성 | 모든 아이콘 버튼 `aria-label`, 키보드로 캘린더 셀 진입, 포커스 링 |
| 품질 게이트 | `tsc` · `eslint` · `jest`(106) · Playwright 헤드리스 스크린샷(PC/390/320, 라이트/다크) |

## 7. 성공 지표

| 지표 | 목표 |
| :--- | :--- |
| 가입 완료율 (이메일 입력 → 가입) | 70% 이상 |
| 첫 일정 등록까지 | 가입 후 5분 이내 50% |
| 그룹 참여율 | 가입자의 40%가 1개 이상 그룹 |
| 모바일 비중 | 세션의 50% 이상 (모바일 우선 설계 검증) |

## 8. 알려진 문제 (2026-09 QA)

| 심각도 | 내용 | 위치 |
| :--- | :--- | :--- |
| 🔴 | 회원가입 전화번호 — 구글 가입자는 번호가 없으므로 선택이 의도. 백엔드 `@NotBlank` 제거, `@Pattern`은 `^$|…`로 빈 값 허용 | `MemberSignupRequest` |
| 🔴 | 가입 신청 메시지 201자 → 500 (Oracle 바이트 길이) | `TB_GROUP_JOIN_REQUEST.message` |
| 🟠 | 미니 달력 공휴일이 스케줄 store 달을 따라감 | `MiniCalendar.tsx` |
| ⚪ | 로그아웃 후 access-token이 만료(30분)까지 유효 — **설계상 허용**. HttpOnly 쿠키라 탈취 경로가 좁고, 로그아웃 시 refresh는 즉시 폐기되어 재진입은 불가. 블랙리스트는 Redis 도입 시 검토 | JWT 설계 |
| 🟡 | 모바일 터치 타깃 32px 미만 일부 | 가이드 닫기, 전체 보기, 초대 코드 복사 등 |
